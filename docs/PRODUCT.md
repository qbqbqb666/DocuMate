# DocuMate 产品文档

## 1. 产品概述

DocuMate 是一款面向个人用户的智能文档 Agent，由个人独立开发。项目以学习和实践 LangChain、LangGraph 及 Agent 工程化开发为主要出发点，通过真实产品开发过程理解模型调用、工具使用、状态管理、上下文管理、长期记忆、权限确认及 Agent 工作流编排。

DocuMate 的目标不是单纯提供一个聊天界面，而是成为能够理解用户意图、读取文档内容、调用工具并完成实际文档任务的智能助手。

产品计划支持 PDF、Word、Excel 等常见文档，以及文本文件和图片。Agent 能够识别文件类型、读取文件内容、理解文字与图片信息，并根据用户要求完成文档存储、查找、整理、生成和修改等操作。

用户通过配置自己的模型 API Key 使用 AI 能力。DocuMate 本身不提供模型服务，而是通过用户授权的 API Key 连接 DeepSeek 等模型服务。API Key 应保存在用户本地，不写入代码，也不提交到版本控制系统。

## 2. 产品目标

DocuMate 主要包含两个目标。

第一，作为一个透明、可学习、可维护的 Agent 项目，帮助开发者逐步理解：

- LLM 如何接收并生成消息；
- Python 函数如何被定义为 Tool；
- 模型如何判断是否需要调用 Tool；
- LangGraph 如何通过 State、Node、Edge 和 Routing 编排 Agent；
- Agent 如何管理 Context 和对话历史；
- Checkpointer 和 Store 如何实现短期记忆与长期记忆；
- Agent 如何在敏感操作前暂停并等待用户确认；
- Agent 如何通过 FastAPI 和流式接口接入前端。

第二，作为一款实际可用的文档处理工具，帮助用户减少重复的文件管理和内容处理工作，并逐渐学习用户的使用习惯。

## 3. 基础功能

### 3.1 模型对话

- 接收用户自然语言指令；
- 调用用户配置的模型；
- 支持流式输出；
- 保存同一会话中的上下文；
- 支持创建和继续不同会话。

### 3.2 Agent 工作流

- 使用 LangGraph 编排 Agent 执行流程；
- 由模型判断是否需要调用工具；
- 将工具执行结果返回给模型；
- 支持 Model、Tool、Model 的循环；
- 保存和展示 Agent 的关键执行过程；
- 避免将核心 Agent 逻辑封装为不可理解的黑箱。

### 3.3 工具系统

- 将明确、安全的 Python 函数注册为 Tool；
- 为每个 Tool 定义清晰的名称、参数和说明；
- 区分只读工具与具有修改能力的工具；
- 限制工具只能访问用户授权的工作区；
- 记录工具调用请求、执行结果和错误。

### 3.4 上下文与记忆

- 使用 State 保存单次运行中的消息和中间结果；
- 使用 Checkpointer 保存同一会话的历史和执行进度；
- 使用 Store 保存跨会话的长期信息；
- 支持记录用户偏好、常用工作区和文档处理习惯；
- 控制上下文长度，避免无限累积历史消息。

### 3.5 权限确认

只读操作可以直接执行，例如：

- 列出工作区文件；
- 查看文件信息；
- 读取文档内容；
- 搜索文档。

可能改变用户数据的操作必须经过确认，例如：

- 创建文件；
- 修改文件；
- 删除文件；
- 移动或重命名文件；
- 覆盖已有内容；
- 执行外部命令。

LangGraph 应在敏感操作前暂停工作流，向前端返回待确认信息，并在用户同意后恢复执行。

## 4. 专业文档能力

在基础 Agent 稳定后，DocuMate 将逐步增加以下专业能力。

### 4.1 文档读取与识别

- 读取 PDF、DOCX、XLSX、TXT 等文件；
- 提取文档正文、表格和基础元数据；
- 识别扫描件和图片中的文字；
- 使用多模态模型理解图片内容；
- 根据文件类型选择合适的解析工具。

### 4.2 文档管理

- 列出和搜索工作区文件；
- 根据内容、类型、名称或时间筛选文件；
- 创建文件夹和整理文件；
- 移动、重命名和删除文件；
- 记录文件变更；
- 在执行修改前获得用户确认。

### 4.3 文档内容操作

- 根据用户要求生成文档；
- 修改已有文档内容；
- 提取摘要、重点和结构；
- 对文档进行分类；
- 比较多个文档之间的差异；
- 从文档中提取表格和结构化信息；
- 根据用户要求生成 Word、PDF 或 Excel 文件。

### 4.4 用户习惯学习

DocuMate 可以从用户明确授权的历史任务和文档中提取偏好，例如：

- 常用文档格式；
- 标题和排版习惯；
- 常用语气；
- 文件命名规则；
- 常用目录；
- 报告结构；
- 表格样式。

这些信息通过长期记忆保存。Agent 在使用长期记忆前应明确其来源，并允许用户查看、修改或删除已经保存的偏好。

## 5. 第一阶段最小版本

第一阶段不追求完整的文档处理能力，只实现一个最小但完整、透明且可验证的 Agent：

```text
用户输入
→ LangGraph State
→ Model Node
→ 判断是否需要 Tool
→ 调用 list_workspace_files
→ Tool 结果写回 State
→ Model 根据结果回答
→ 返回最终消息
```

第一阶段只提供一个只读工具：

```python
list_workspace_files()
```

该工具只能列出授权工作区中的文件，不允许写入文件、删除文件或执行 Shell 命令。

第一阶段的成功标准是：

- 普通问题可以由模型直接回答；
- 文件相关问题能够触发工具调用；
- Agent 根据真实工具结果回答；
- 可以观察完整的消息与工具调用过程；
- 图能够正常结束，不产生无限循环；
- 同一会话可以在后续阶段通过 Checkpointer 保留上下文。

## 6. 技术栈

### 6.1 后端

- Python：主要开发语言；
- uv：管理 Python 版本、虚拟环境、项目依赖和锁文件；
- LangChain：提供 Model、Message、Tool 等基础组件；
- LangGraph：编排 State、Node、Routing、Agent Loop 和权限确认流程；
- FastAPI：提供 HTTP 和流式聊天接口；
- SQLite：保存本地会话、Checkpoint、用户配置及长期记忆；
- python-dotenv：读取本地环境变量。

### 6.2 模型服务

- DeepSeek：第一阶段优先使用的聊天模型；
- SiliconFlow：后续可扩展的模型服务；
- OpenAI 兼容接口：用于统一不同模型服务的调用方式。

### 6.3 前端

- React；
- TypeScript；
- Vite；
- 沿用已有 DocuMate UI 设计并逐步接入新后端。

### 6.4 开发环境

- macOS；
- PyCharm；
- Jupyter Notebook：用于分步骤实验和学习；
- Git：用于版本管理；
- pytest：用于后端测试；
- Ruff：用于 Python 代码检查和格式化。

## 7. 开发原则

DocuMate 的开发遵循以下原则：

- 教学和可理解性优先；
- 每次只完成一个可以独立验证的小步骤；
- Agent 的 State、Node、Routing 和 Tool 调用过程保持透明；
- 先在 Notebook 中进行实验，再整理到正式模块；
- 先实现正常流程，再逐步加入异常处理；
- 先实现只读能力，再增加修改能力；
- 所有敏感操作必须经过明确的权限确认；
- 不在代码中保存 API Key；
- 不在第一阶段引入复杂 RAG、OCR、向量数据库或多 Agent；
- 每个模块只承担一种主要职责；
- 每一次功能扩展都应具备明确的测试和验收标准。

## 8. 长期愿景

DocuMate 的长期目标是成为一个本地优先、权限透明、可以理解用户习惯的个人文档智能体。

它不仅能够回答关于文档的问题，还能够在用户授权下完成实际工作；同时让用户清楚看到 Agent 为什么调用工具、读取了什么数据、准备执行什么操作，以及哪些长期信息被保存。
