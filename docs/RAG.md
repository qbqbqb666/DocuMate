# 本地基础资料检索

仅当 Agent 调用 `search_workspace_documents` 查找与需求相关的工作区文件时，graph 从 approval 路由到 retrieval，再回 summarize/model。普通聊天、文件名搜索及明确路径的读取不进入该节点。调用选择由聊天模型依据工具说明和系统提示词决定，未经实测不应视为自然语言意图判断完全可靠。

## 本地运行

执行 `uv sync --locked --default-index https://mirrors.tuna.tsinghua.edu.cn/pypi/web/simple/` 安装锁定依赖。模型资源放在 `src/backend/data/models/multilingual-e5-small/`，或用 `DOCUMATE_EMBEDDING_DIR` 指定本地目录；加载 `model.onnx` 和 `tokenizer.json` 时不联网。开发模式可从项目已有资源目录加载；打包时将模型资源和 ONNX/tokenizer/sqlite-vec 运行依赖收入冻结后端，正式版从包内 `models/multilingual-e5-small/` 加载。可执行冻结后端的 `--check-local-retrieval` 检查离线模型与向量扩展。模型目录受 Git 忽略，其他构建机器须先准备相同模型资源。

共用解析器 `parse_document` 读取 PDF、DOCX、XLSX、UTF-8 TXT/Markdown，并保留页码、段落、表格行、工作表和文本行位置。原文件不复制、不备份。扫描 PDF 暂无 OCR。单文件上限 50 MB；扫描跳过隐藏文件夹、缓存和符号链接，单次扫描上限 20000 份资料。为兼容旧版导入，单独纳入所选文件夹的 `.documate/documents/`，其他隐藏目录保持排除。

基础版 E5 输入按 320 tokens 分块、40 tokens 重叠，问题加 `query: `，正文加 `passage: `，平均池化后 L2 归一化，输出 384 维。使用 SQLite/sqlite-vec 保存原文件版本、来源及向量，并在限定路径范围内精确计算余弦距离，按最佳命中归并文件。没有查询改写、翻译、重排模型或近似近邻索引。Top-K 是候选，不保证相关，无依据问题仍需 Agent 核对。

## 索引一致性

索引位于应用本地数据目录 `retrieval.sqlite3`，独立于已有对话数据库。后台每 2 秒核查文件状态，连续保存稳定 5 秒后处理；同一服务串行处理，未变化内容复用已有向量。记录大小、纳秒修改／状态变化时间、inode 及内容 SHA256。修改后标记 pending 并停用旧结果，解析编码期间再次修改不发布旧版本。新文本块和向量在单一 SQLite 事务中替换；删除文件清除其索引。解析失败仅影响该文件，保留错误并后台重试。

后端启动时检查当前工作区，检索前补查指定范围；项目其他已检索文件夹由后台继续维护。首次发现文件会立即处理其已保存版本；后续保存合并更新。关闭应用停止后台线程，未完成工作在下次扫描重试。检索结果返回 ready/pending/error 状态、原文件绝对路径、版本哈希、命中片段及位置，可由现有读文件工具继续核对。它不负责生成回答或实现前端文件引用按钮。

## 验证边界

`tests/test_retrieval.py` 使用真实 E5、实际生成的五种格式样例和真实 sqlite-vec；包含长文本、路径范围、更新／删除、失败恢复、模型版本、连续保存、启动补查和 graph 调用测试。生产 graph 测试中的聊天模型输出固定，检索不模拟；自然语言选工具及真实云模型回答尚未完整 UI 实测。

此前中文查英文备份资料的 Top-1 失败保留，未通过查询优化消除。不得将结构与一致性测试通过宣传为检索相关性全部通过。千份文件容量、Windows 和桌面打包须分别报告验证范围，不能用重复短文件推断千份长 PDF 的性能。


## v0.6.0 本地发布准备（2026-10-14）

- 原文件区及文件引用选择器复用目录接口；旧导入文件保持原位置，以兼容入口展示，个人中心数量与文件区一致。
- 预览按大小、mtime/ctime、inode 检查版本，未变化只返回状态，不重新解析正文。
- 对话创建失败、HTTP 失败、模型错误及无结果连接中断时保留输入文字和引用；成功或请求批准后清空，主动停止按用户取消处理。
- 应用、桌面本地 API 和本地下载/更新元数据均为 0.6.0；历史版本记录、第三方依赖及认证服务自身 API 版本保持各自含义。
- Python 162 项、Electron 17 项、前端构建、锁文件和 diff 检查通过。草稿与引用的五种发送结果使用隔离接口故障回归验证，没有调用云模型。
- Mac arm64 冻结后端在空用户目录中验证实际 tokenizer、ONNX CPU、sqlite-vec、启动、旧资料列表/统计、预览版本和 2 份真实文件后台索引。
- Windows 打包脚本已接入相同资源规则及冻结后端模型检查，尚未在 Windows 上执行。Windows ARM64 仍属暂缓范围。
- 未生成正式 Electron 安装包，未验证两平台安装/升级完整 UI，未推送或部署。
- 按用户决定，只有一行内容的 XLSX 被当表头而没有解析块的问题暂不修复；基础跨语言检索已知失败样例也未优化。
